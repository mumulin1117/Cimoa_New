# 聊天详情：去除冗余保存弹层

## 用户要求与根因

用户指出消息详情中的 `Saving message` 冗余。旧页面的同一个 `is_loading` 同时控制已读同步、消息发送、发起通话和安全操作，并统一回退到全屏 `Saving message…`；因此进页标记已读和开始通话也会出现错误的保存提示。

## 实现边界

- 普通文字发送：原发送按钮内显示无文字转圈与 `aria-busy`，不出现遮罩、保存弹层或成功 Toast；完成后恢复原图标。
- 图片/语音发送：原确认按钮内显示相同的轻量请求态；不改变预览、真实媒体、失败重试或数据保存流程。
- 发起通话：视频按钮内显示请求态，仍仅创建既有等待接通流程，不模拟已接通。
- 已读同步：独立受控 Loading，在消息内容区右上显示小型指示，不锁输入、返回或滚动；离页、账号变化、权限失效均取消未完成任务。
- 拉黑和明确的通知偏好操作保留原自定义业务反馈。本次不全局移除其他业务的 Loading，也不修改活动群聊页面。
- 继续使用 `use_write_loading` 的 400–600ms 时序，完成后才执行 Store action；不把业务写入改为无请求态或提前写入，不隐藏真实错误。
- 页面不直接读写 storage，不增加重复业务数据。`ChatActionLoading.vue` 使用 uni-app 组件、rpx 与既有主题变量，不更改正常静止状态的原型图标与布局。
- 两份开发/交互约定与 HTML 原型均未修改。已更新既有聊天回归脚本中指向全屏 Loading 的旧断言，使其检查对应按钮/已读状态，而非继续要求冗余弹层。

## 验证说明

浏览器和 WKWebView 共用 `scripts/lib/chat-feedback-regression.mjs`，覆盖进页已读、输入可用、提前返回取消、一次发送、重复点击、存储失败保留草稿、重试、等待通话返回、真实包内图片预览与发送、发送中离页取消和刷新恢复。

图片测试使用包内真实图片 Blob 和 IndexedDB，不调用相机/相册系统授权。输入通过 DOM 事件，不宣称本次覆盖了系统软键盘；语音的请求态复用同一媒体确认按钮，本轮未新增真实麦克风录制。原有媒体校验/补偿相关单元测试仍执行。

临时 H5 测试服务记录 PID 并在 finally 关闭；WKWebView 测试备份和恢复两个业务 storage key，并移除新产生的测试图片 Blob。历史注册截图不属于本次修改，保持不暂存。

测试最初发现的断言时序问题已改为等待 Vue 实际清空输入框，而不是在 storage 完成的同一个微任务内断言 DOM 已同步；没有以固定延迟掩盖发送或持久化错误。最终结果见同目录 `acceptance.json`。
